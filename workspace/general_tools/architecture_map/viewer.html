SOURCE EVIDENCE



Read the map with confidence.

  
Level 1 explains the main ideas. Level 2 is the source snapshot, with the complete module inventory and evidence. Level 3 receives regenerated data while the local watcher is running.

  
Timeline adds documented decisions and daily source changes from retained Git history. Reasons are attributed to development notes; automatic-save messages cannot establish intent. Use the glossary, guided flows, saved parts and component work briefs to connect an explanation to your next change.

  
An import means code depends on a module. A resolved call means the caller and target could be identified statically. Neither proves that a branch executed. Reviewed connections explain callbacks, files, events and network seams with source references.

  
Descriptions and reviewed connections carry hashes of the code that was inspected. When it changes, the map flags them for review instead of silently presenting old explanations as current. New modules, imports, resolved calls and endpoint defaults are discovered automatically.

  
Dynamic receivers and third-party operations cannot all be inferred from Python source. They remain visible as unresolved references. Unused imports do not prove that a capability runs; an absence of imports does not prove it can never be called dynamically.

  
Detachable tool internals, model binaries, personal memory contents, generated code, tests and archived copies are not expanded. Launch/chat seams remain visible where they touch the body. Live status checks only whether a configured local port accepts a TCP connection.

  
To start automatic updates, run Orient\Architecture\RUN_MAP.cmd. It watches source, catalog, viewer assets, relevant configuration definitions and mapped file metadata. Keep the watcher running for updates; STOP_MAP.cmd stops only the atlas.
