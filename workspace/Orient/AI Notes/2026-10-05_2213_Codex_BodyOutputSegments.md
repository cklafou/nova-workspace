# Body-owned output segments

**Summary:** The optional segmented delivery path preserves useful completed work while the same body-owned turn continues. New input does not cancel inference or restart the task. This supersedes the single-final-output behavior described in the 2147 continuation note when a caller supplies `on_segment`.

## Did
- `workspace/nova_body/nova_runtime/model_client.py` forwards optional `on_segment(text, metadata)` only to Nova. Legacy callers without it retain their callback contract.
- `nova_voice/nova.py` sends every committed nonempty segment, including the last, through that callback. Metadata contains stable `turn_id`, one-based `segment_index`, `input_revision`, candidate-bound `audit`, and `final`. `on_done` fires once with the aggregate committed text as a terminal notification. Adapters must not render or speak that aggregate a second time.
- The segmented prompt documents a body control: `{"tool":"speak","args":{"text":"visible completed segment","continue":true}}`. The text passes through the existing exact-candidate audit pipeline. It is not hidden thought, does not bypass the witness, and is not dispatched as a computer tool. Continue true keeps the same run working. Normal prose or continue false finishes if no new input waits. Empty speak text does not request endless continuation. No token slicing or provider control endpoint was added.
- When input arrives during a segment audit, the completed segment can still be delivered against its frozen input revision. The next boundary consumes the queued input and tells Nova to reconcile/correct changed conclusions explicitly without repeating delivered work. Unexecuted side-effect proposals still re-evaluate queued input before dispatch. Explicit Stop still withholds undelivered output.
- `nova_cortex/witness.py` accepts an optional bounded evidence snapshot. The body captures the human/wire/session records before a provider step; audit reads reuse that snapshot instead of changing the candidate's conversation underneath it. Actual completed tool receipts and images remain audit inputs. Default prompt content and strict verdict parsing are unchanged.
- Follow-ups no longer replenish total tool-loop or witness-revision allowances. Reaching the work limit emits an honest NOT_RUN remainder notice. The terminal budget path consumes already-admitted input then seals before an observer can admit stranded follow-ups.
- `nova_runtime/conversation.py` provides cancellation checks compatible with tasks lacking Python 3.11's `cancelling()` counter. On older Python, ambiguous observer CancelledError propagates conservatively rather than swallowing explicit Stop.
