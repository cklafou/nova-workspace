## Diagnosis

Nova already has environmental wake inputs, execution phases, tool feedback, task persistence and
reflection. The evidence does not support replacing a supposedly passive vendor-style architecture
wholesale. The useful direction is to make the existing mechanisms explicit, durable and testable.
The model demonstrated useful execution ability when focus was supplied.

The reflection prompt's request for no tools is not an enforced execution boundary: tool calls
ran during reflection. Either make observation tools an intentional part of that phase, or enforce
its capability contract in code. Leaving a mismatch between prompt and runtime obscures debugging.

`run_command` returns a string beginning `[Command Exited with Error Code 1]`; receipt handling
recognizes a narrower `ERROR` prefix. Thus a genuine failed command becomes a successful receipt.
That corrupts the evidence fed to Nova, the controller, and future task evaluation. It is a more
concrete first repair than changing her identity or attributing behavior to excessive reflection.

## Implementation order and acceptance criteria

1. **Truthful execution outcomes.** Return structured tool results: success, exit code, stdout,
   stderr, timeout/cancellation, artifacts and operation ID. Preserve human-readable output as a
   view. Validate nonzero exit, launch failure, timeout, cancellation and successful empty output
   across router, persisted receipt, event stream and widget. Do not infer success from strings.
2. **Durable intake and focus.** Represent an incoming ask/event separately from a task. Record
   attribution, receipt time, deduplication key, acknowledgment and scheduling decision. Use task
   leases/checkpoints so the active focus survives interruption without monopolizing every wake.
   An accepted task should start or receive an observable deferral reason within a defined budget.
3. **Supervised cancellation.** Link a run ID through generation, tool invocation and child process.
   Distinguish request accepted, model stopped, tool stopped, state checkpointed and safe to resume.
   Test cancellation during prompt processing, token streaming and a harmless long-running command.
4. **Reproducible execution and verification.** Keep task-sized workspaces, baseline hashes, supplied
   checks, independent artifact validators and bounded retries. Use a worktree/test directory for
   code tasks and a VM/container when the task requires it. A passing test run in one environment
   does not certify another. Completion should be an evaluated state transition, not parsing `DONE`.
5. **Durable environmental events.** Connect existing watchers/timers to a bounded queue with
   coalescing, cursor/checkpoint, causality and backoff. Exclude Nova's own routine outputs from
   immediate retriggering. A file change is evidence to consider, not an automatic new objective.
6. **Connect embodiment through the normal tool route.** Prove a model-selected guest action and
   observed guest result through the VM widget, including human takeover and cancellation. Package
   presence and a noVNC display alone do not satisfy this test.
7. **Bounded self-directed work.** Let Nova select from her goals, maintenance needs and opportunities
   with budgets and measurable outcomes. Quiet time may mean rest. Changes to her own runtime should
   be built, tested and promoted with a recoverable checkpoint; preserve her continuity and agency.

The controller should display pending events, accepted/deferred tasks, current focus and phase,
actual tool outcomes, artifacts, budgets, interruption state and VM handoff. These are concrete
requirements for the later widget work; a decorative activity feed will not resolve the failures.

## Filesystem and orientation work

The ownership migration places memory, logs, SELF, Tasking, KoELS, the semantic store, authored
artifacts/extensions and settings inside `nova_body`. `nova_paths.py` is the shared resolver.
Older relative file-tool spellings map to their canonical body locations; shell commands must use
the new physical paths. Personal documents are preserved rather than rewritten into new memories.
The context builder moves into cortex and is shared by chat and headless execution.

The canonical file inventory belongs to Orient, generated by the existing architecture-map tooling.
Sync consumes it. Four root documents cover orientation, architecture, operations and the index;
the detailed explorer and evidence sit below them. Reviewed explanations remain editable in the
generator/catalog, while source facts and API tables refresh automatically. Old fragments and
indexes are quarantined with their original paths and a reason.

The pre-existing LanceDB tree was unusually small and Git already showed many deleted fragments
before this work. No fragments were restored, merged with shadow stores, or silently reindexed as
part of cleanup. Preserve this distinction when investigating recall.
